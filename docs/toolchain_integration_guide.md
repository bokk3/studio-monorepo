# Toolchain Integration Guide
**Target:** In-Office and Remote Developers & AI Agents
**Scope:** Fusion 360, Blender, Godot 4.x, and Unreal Engine 5 (UE5)

This document outlines how human developers and AI agents collaborate across our multi-engine pipeline. Whether you are working from the central office or remoting in from home, these standard operating procedures (SOPs) ensure assets flow frictionlessly from mechanical design into real-time engines.

---

## 1. Autodesk Fusion 360 (Mechanical CAD)
*Role: Primary authoring tool for hard-surface models, vehicles, and weapons.*

### For Human Developers:
- **In-Office / Remote:** Work natively in the Fusion 360 cloud environment. Keep your assemblies structured hierarchically (e.g., `Hull`, `Engines`, `Cockpit`).
- **Export Standards:** Do not rely on manual polygon exporting. Save parametric designs to the shared cloud project.

### For AI Agents & Pipeline:
- **Headless Processing:** Agents cannot click the Fusion UI. We utilize the **Fusion 360 Python API** to run batch extraction scripts.
- **Agent Workflow:**
  1. AI monitors the Fusion cloud directory (via Autodesk Forge API).
  2. Extracts `.STEP` files automatically when an artist tags a version as `Release-Candidate`.
  3. Hands off the `.STEP` mathematical data to the Blender pipeline for meshing.

---

## 2. Blender (The Processing Bridge)
*Role: Mesh conversion, LOD generation, normal baking, and UV mapping.*

### For Human Developers:
- **Usage:** Use Blender purely for shader painting, rigging organic meshes, or tweaking AI-generated LODs. 
- **Sync:** Commit your `.blend` files to Git LFS inside `studio-monorepo/assets/raw`.

### For AI Agents & Pipeline:
- **Headless Execution:** AI agents will run Blender completely invisibly via the CLI using Python scripts:
  ```bash
  blender --background --python scripts/asset-pipeline/cad_to_mesh.py -- input.step
  ```
- **Agent Workflow:**
  1. Ingest `.STEP` files from Fusion 360.
  2. Procedurally generate polygons based on angle thresholds.
  3. Auto-generate LOD0 (48k tris), LOD1 (18k tris), LOD2 (4k tris), and a convex collision hull.
  4. Auto-unwrap UVs and bake sharp edges to normal maps.
  5. Export universally to `.GLTF` (for Godot) and `.FBX` (for Unreal Engine).

---

## 3. Godot 4.x (Primary AA Engine)
*Role: Current production engine for web gateways, mobile play, and lightweight PC releases.*

### For Human Developers:
- **In-Office / Remote:** Standard Git workflow. Keep the editor open, pull the latest `res://` assets generated by the AI.
- **Networking:** Test local multiplayer seamlessly via the embedded `TCPServer` and `WebSocketPeer` implementations. No external servers needed for local iteration.

### For AI Agents & Pipeline:
- **Headless CI/CD:** Agents run Godot without a GUI to validate code and physics.
  ```bash
  godot --headless --path apps/game-client -s test_suite.gd
  ```
- **Agent Workflow:**
  1. Automatically write GDScript unit tests when humans push netcode or physics logic.
  2. Validate `.GLTF` imports by instantiating scenes headlessly and checking node hierarchies.
  3. Generate procedural `.tscn` (scene) files directly from scripts if batch-creating levels.

---

## 4. Unreal Engine 5 (Future AAA Engine)
*Role: Target engine for future cinematic, high-fidelity console/PC releases.*

### For Human Developers:
- **Setup:** Both remote and in-office devs will utilize **Unreal Game Sync (UGS)** and Perforce (Helix Core) or Git-LFS (if scaling permits) for binary asset distribution.
- **Nanite Integration:** When we shift to UE5, we will bypass heavy LOD generation in Blender. Instead, the raw, ultra-dense meshes from Fusion 360 will be fed directly into Nanite.

### For AI Agents & Pipeline:
- **Python Automation API:** UE5 has a robust Python API. AI agents will drive Unreal Engine headlessly using Python commandlets.
  ```bash
  UnrealEditor-Cmd.exe "C:\Project\Game.uproject" -ExecutePythonScript="scripts/ue5_import.py" -NoUI
  ```
- **Agent Workflow:**
  1. **Datasmith Pipeline:** Agents will automate Datasmith CAD imports for Fusion 360 files.
  2. **Material Translation:** AI will automatically map Blender PBR exports into Unreal Master Material instances.
  3. **Blueprint Scaffolding:** AI will generate base C++ classes and expose them to Blueprints, providing humans with the skeleton architecture for AI logic and GameModes.

---

## Summary of the Universal Asset Flow
1. **Design:** Human creates NURBS in Fusion 360.
2. **Bridge:** AI triggers Blender in the background to convert NURBS to `.GLTF` and `.FBX`.
3. **Branch A (Godot):** AI commits `.GLTF` to the Godot `res://` directory and runs headless physics tests.
4. **Branch B (Unreal):** AI executes UE5 Python scripts to pull `.FBX` into the Content Browser, assigning Nanite and Lumen settings automatically.
